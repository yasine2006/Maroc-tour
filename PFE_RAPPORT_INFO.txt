          2. RESUME DU PROJET — ملخص المشروع
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MarocTour est une application web complete dediee au tourisme au Maroc.
Elle integre trois services intelligents:

  Service 1 — Prediction de destination (SVM):
    L'utilisateur entre son profil (age, sexe, budget, situation maritale,
    region d'origine). Un modele SVM (Support Vector Machine) predit
    le type de destination recommandee (Ville ou Nature), puis propose
    les lieux correspondants avec descriptions detaillees.

  Service 2 — Planificateur de voyage:
    Generation automatique d'un plan de voyage jour par jour avec
    activites, couts, horaires et conseils pratiques.

  Service 3 — Groupes de voyage intelligents (KMeans + Cosine Similarity):
    Systeme de matching IA entre le profil du voyageur et les groupes
    de voyage existants, en utilisant le clustering KMeans et la
    similarite cosinus pour calculer un score de compatibilite.

          3. PROBLEMATIQUE — الاشكالية
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Le tourisme au Maroc souffre de plusieurs lacunes:

  - Le voyageur ne sait pas quelle destination choisir selon son profil
  - Les plateformes existantes proposent des suggestions generiques
    sans personnalisation basee sur les donnees de l'utilisateur
  - Il n'existe pas de systeme intelligent pour former des groupes
    de voyage compatibles entre voyageurs

Notre solution:
  Utiliser le Machine Learning pour personnaliser les recommandations
  touristiques en fonction du profil reel de chaque voyageur,
  et un systeme IA de matching pour les groupes de voyage.

          7. SERVICE 1 — MODELE SVM (Support Vector Machine)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Objectif: Predire le type de destination (Ville ou Nature)
          a partir du profil du voyageur.

7.1 Donnees d'entrainement (data.csv):
  - 1,050 lignes apres optimisation
  - Features: age, sexe, budget, marie, region_origine
  - Target: type_destination (Ville / Nature)
  - Inclut 20 "noise cases" pour eviter l'overfitting:
      * Jeunes avec budget eleve preferant Nature
      * Personnes agees avec petit budget preferant Ville

7.2 Preprocessing:
  a) LabelEncoder: convertit les variables categoriques en nombres
       Homme/Femme   => 0/1
       Oui/Non       => 0/1
       France/Maroc/... => 0/1/2/...
  b) StandardScaler: normalise les valeurs numeriques
       moyenne = 0, ecart-type = 1
       Necessaire pour SVM (sensible aux echelles)

7.3 Division Train/Test:
  - 70% entrainement (721 lignes)
  - 30% test interne  (309 lignes)
  - stratify=y: distribution equilibree Ville/Nature dans les deux ensembles

7.4 Modele SVM choisi:
  SVC(kernel='rbf', C=1.0, gamma='scale',
      class_weight='balanced', probability=True)

  Pourquoi SVM et pas Random Forest?
  ┌────────────────────┬──────────────────┬───────────────────┐
  │ Modele             │ Accuracy Train   │ Accuracy Externe  │
  ├────────────────────┼──────────────────┼───────────────────┤
  │ Random Forest      │ 98.64%           │ 96.0% (3 erreurs) │
  │ SVM (rbf)          │ 97.82%           │ 100% (0 erreur)   │
  └────────────────────┴──────────────────┴───────────────────┘
  => SVM generalise mieux sur des donnees inconnues

  Parametres expliques:
    kernel='rbf'     : Radial Basis Function — frontiere non lineaire
    C=1.0            : regularisation — equilibre precision/generalisation
    gamma='scale'    : gamma calcule automatiquement selon les donnees
    class_weight='balanced' : evite le biais vers la classe majoritaire
    probability=True : permet de calculer les probabilites de prediction

7.5 Evaluation — 3 niveaux:
  Niveau 1 — Split interne (30%):
    Accuracy = 97.46%

  Niveau 2 — Cross-validation 5-fold:
    Principe: diviser les donnees en 5 parties egales
              tester 5 fois avec un fold different comme test
    Resultat: 96.19% (+/- 4.13%)
    Avantage: evaluation plus fiable qu'un seul split

  Niveau 3 — Test externe (test_model.csv):
    25 cas jamais vus pendant l'entrainement
    Inclut des cas difficiles (budget moyen, age moyen)
    Resultat: 100% (25/25 corrects)
    Conclusion: le modele comprend, il ne memorise pas

  Difference train/externe = -2.2% (negative = tres bonne generalisation)

7.6 Flux complet Service 1:
  [1] Utilisateur entre: age=25, sexe=Femme, budget=1500, marie=Non, region=Maroc
  [2] LabelEncoder convertit les textes en nombres
  [3] StandardScaler normalise les valeurs
  [4] model.predict() => "Nature"
  [5] obtenir_lieux("Nature", 1500) => liste des sites naturels dans budget
  [6] Ajout des descriptions de ENRICHISSEMENT_LIEUX
  [7] Retour JSON avec type, lieux, raisons, accuracy du modele

          8. SERVICE 3 — KMEANS + COSINE SIMILARITY (Matching IA)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Objectif: Trouver les groupes de voyage les plus compatibles
          avec le profil d'un voyageur, en utilisant deux algorithmes IA.

8.1 Phase 1 — KMeans Clustering:

  Principe:
    KMeans divise les voyageurs en K=4 groupes (clusters) automatiquement
    selon leurs caracteristiques numeriques.

  Features utilisees: age, budget, sexe (encode), marie (encode)
  Nombre de clusters: 4

  Resultat obtenu sur nos donnees:
  ┌─────────────┬──────────────────────────────────────────────┐
  │ Cluster     │ Type dominant                                │
  ├─────────────┼──────────────────────────────────────────────┤
  │ Cluster 0   │ Ville  (ages moyens, budget eleve, maries)   │
  │ Cluster 1   │ Nature (jeunes, petit budget, celibataires)  │
  │ Cluster 2   │ Ville  (hommes actifs, budget moyen-eleve)   │
  │ Cluster 3   │ Nature (ages varies, budget modeste)         │
  └─────────────┴──────────────────────────────────────────────┘

  Utilisation:
    => Predire le cluster du voyageur => connaitre son type prefere
    => Si le groupe correspond au type predit: +20% bonus au score

8.2 Phase 2 — Encodage vectoriel (encode_profile_vector):

  Chaque profil (utilisateur ou groupe) est converti en un vecteur
  numerique de 24 dimensions:

  ┌─────────────────────────────────────────────────────────────┐
  │ Dimension 1   : age normalise (0 a 1)                       │
  │ Dimension 2   : budget normalise (0 a 1)                    │
  │ Dimensions 3-8: type_activite (one-hot, 6 valeurs)          │
  │                 [Ville, Aventure, Culture, Plage, Montagne,  │
  │                  Mixte] => ex: Aventure = [0,1,0,0,0,0]     │
  │ Dimensions 9-12: niveau (one-hot, 4 valeurs)                │
  │                  [Tous niveaux, Debutant, Intermediaire,     │
  │                   Avance] => ex: Debutant = [0,1,0,0]       │
  │ Dimensions 13-24: interets (multi-hot, 12 valeurs)          │
  │                   [Randonnee, Photo, Gastronomie, Histoire,  │
  │                    Surf, Camping, Musique, Meditation,       │
  │                    Escalade, Artisanat, Desert, Plongee]     │
  └─────────────────────────────────────────────────────────────┘

8.3 Phase 3 — Cosine Similarity:

  Formule:
    cos(theta) = (A . B) / (||A|| * ||B||)
    A = vecteur utilisateur, B = vecteur groupe

  Interpretation:
    cos = 0.0  => profils completement differents
    cos = 0.5  => compatibilite moderee
    cos = 1.0  => profils identiques

  En pratique sur nos donnees:
    sim >= 0.85 => "Excellente compatibilite IA"
    sim >= 0.65 => "Bonne compatibilite IA"
    sim >= 0.45 => "Compatibilite moderee"

8.4 Calcul du score final (0-100):

  score = (cosine_similarity + bonus_kmeans - penalites) * 100

  Bonus KMeans:
    +20% si le type du groupe = type predit par KMeans
    +8%  si le groupe est de type "Mixte"

  Penalites (contraintes dures):
    -25% si l'age de l'utilisateur hors de la tranche du groupe
    -20% si le budget de l'utilisateur insuffisant

  Exemple:
    cos = 0.75, cluster_bonus = 0.20, penalite = 0
    score = (0.75 + 0.20) * 100 = 95%
    Message: "IA predit Nature pour ton profil"

8.5 Comparaison avec l'ancienne methode:

  AVANT (regles manuelles):
    if type_activite == groupe.type: +40 pts
    if niveau == groupe.niveau: +25 pts
    if age in [age_min, age_max]: +20 pts
    if budget >= budget_groupe: +15 pts
    => Score base sur des seuils fixes, subjectifs

  APRES (IA — KMeans + Cosine):
    => Score base sur des calculs mathematiques objectifs
    => Prend en compte la combinaison de TOUS les facteurs
    => KMeans capture des patterns appris depuis les donnees reelles
    => Affiche "IA predit [type] pour ton profil" comme explication

10.2 Analyse de l'overfitting:
  Avant optimisation (Random Forest, 50,000 lignes):
    Train: 100% / Test externe: 88% => Difference = +12% (OVERFITTING)

  Apres optimisation (SVM, 1,050 lignes + noise):
    Train: 97.8% / Test externe: 100% => Difference = -2.2% (BON)

  Solutions appliquees:
    a) Ajout de 20 "noise cases" cassant le pattern trop simple
    b) Reduction des donnees de 50,000 a 1,050 (plus representatif)
    c) Changement de modele: Random Forest => SVM (meilleure generalisation)
    d) Parametre max_depth reduit pour limiter la memorisation

          13. GLOSSAIRE TECHNIQUE — المصطلحات التقنية
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  SVM (Support Vector Machine):
    Algorithme de classification qui cherche l'hyperplan optimal
    separant les classes avec la marge maximale.

  Kernel RBF (Radial Basis Function):
    Fonction mathematique permettant au SVM de tracer des frontieres
    non lineaires entre les classes.

  KMeans:
    Algorithme de clustering qui divise les donnees en K groupes
    en minimisant la distance intra-cluster.

  Cosine Similarity:
    Mesure la similitude entre deux vecteurs par le cosinus de l'angle
    qui les separe. Independante de la magnitude des vecteurs.

  One-hot Encoding:
    Representation d'une variable categorique comme un vecteur binaire.
    Ex: Aventure parmi [Ville, Aventure, Culture] => [0, 1, 0]

  Overfitting (sur-apprentissage):
    Le modele memorise les donnees d'entrainement au lieu d'apprendre
    les patterns generaux. Signe: accuracy train >> accuracy test.

  Cross-validation:
    Technique d'evaluation qui divise les donnees en K folds et
    effectue K evaluations independantes pour un resultat plus fiable.

  StandardScaler:
    Normalisation: soustrait la moyenne et divise par l'ecart-type.
    Resultat: distribution avec moyenne=0 et ecart-type=1.

  REST API:
    Architecture web ou chaque URL represente une ressource.
    Les operations sont: GET (lire), POST (creer), DELETE (supprimer).

  bcrypt:
    Algorithme de hachage unidirectionnel pour les mots de passe.
    Impossible a inverser, inclut un "sel" pour eviter les attaques.

  SQLite:
    Base de donnees relationnelle stockee dans un seul fichier.
    Ideale pour les projets de taille petite a moyenne.

  Stratify:
    Option de train_test_split qui maintient la meme proportion
    de classes dans les ensembles d'entrainement et de test.
