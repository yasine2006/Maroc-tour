MarocTour هو تطبيق ويب (Web Application) كامل للسياحة في المغرب.
مبني بلغة Python باستخدام إطار عمل Flask.

الهدف منه:
  - يساعد المسافر يختار وجهته السياحية بناء على بياناته الشخصية (عمر، ميزانية، جنس...)
  - يولد له خطة رحلة تفصيلية يوم بيوم
  - يساعده يلاقي مجموعات سفر أو ينشئ واحدة
  - عنده نظام تسجيل مستخدمين كامل
  - عنده لوحة إدارة (Admin Panel)

التقنيات المستخدمة:
  ✦ Backend  : Python + Flask
  ✦ ML S1    : Scikit-learn (SVM — Support Vector Machine, kernel rbf)
  ✦ ML S3    : KMeans Clustering + Cosine Similarity
  ✦ Database : SQLite
  ✦ Frontend : HTML + CSS + JavaScript (Vanilla)
  ✦ Security : Werkzeug (bcrypt هاش لكلمات السر)

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)

  → 70% من البيانات (~721 صف) للتدريب

  → stratify=y : باش يكون توزيع Ville/Nature متوازن في كلا القسمين

  ⭐ لماذا 70/30 مو 80/20؟
     → test set أكبر = تقييم أدق وأكثر موثوقية للنموذج

scaler = StandardScaler()

  → المشكلة: العمر (20-80) والميزانية (500-10000) أرقام بمقاييس مختلفة
  → StandardScaler كيحول كل الأعمدة باش متوسطها 0 وانحرافها المعياري 1
  → مهم جدا لـ SVM لأنه حساس لمقياس الأرقام
  → fit_transform على Training set / transform فقط على Test set

model = SVC(

    gamma='scale',           → يحسب gamma تلقائيا بناء على البيانات
    class_weight='balanced', → وزن متساوي للـ classes
    random_state=42,         → للتكرار
    probability=True         → باش يحسب احتمالات (مو فقط الفئة)

  ⭐ SVM شنو هو؟
     = النموذج كيبحث على "hyperplane" (خط أو مستوى) يفصل Ville عن Nature
     = kernel='rbf' كيسمح بحدود غير خطية (منحنيات)
     = C=1.0 : توازن بين الدقة ومنع الـ overfitting

  ⭐ لماذا SVM أحسن من Random Forest في بياناتنا؟
     Random Forest : train=98.6% / test externe=96%  (diff= +2.6%)
     SVM (rbf)     : train=97.8% / test externe=100% (diff= -2.2%)
     → SVM يعمم أحسن على بيانات جديدة لم يرها

model.fit(X_train_scaled, y_train)

API AUTHENTIFICATION
══════════════════════════════

POST /api/register  (إنشاء حساب)
  → يتحقق: اسم، إيميل، كلمة سر (6 أحرف على الأقل)
  → يتحقق: إيميل صحيح (@ و .)
  → يشفر كلمة السر: generate_password_hash(password)
  → يحفظ في users table
  → إذا الإيميل موجود: sqlite3.IntegrityError → رسالة خطأ

POST /api/login  (تسجيل دخول)
  → يجيب المستخدم من DB بالإيميل
  → يتحقق من كلمة السر: check_password_hash(stored, entered)
  → إذا صح: session.clear() ثم يضيف user_id, user_name, user_email للـ session
  → يرجع معلومات المستخدم كـ JSON

POST /api/logout  (خروج)
  → session.clear() — كيمسح كل الـ session

GET /api/current-user  (معلومات المستخدم الحالي)
  → إذا user_id فالـ session → يرجع معلوماته
  → إذا لا → {"logged_in": false}

POST /api/forgot-password  (نسيت كلمة السر)
  → Demo فقط — يقول "تم إرسال إيميل"
  → ما يظهرش الـ hash أبدا للأمان

  التحقق من المدخلات:
    - age بين 10 و 110
    - budget >= 500 MAD
    - sexe = Homme أو Femme
    - marie = Oui أو Non

  العملية:
    1. type_dest = predire_destination(...)  ← Ville أو Nature
    2. lieux = obtenir_lieux(type_dest, budget)  ← قائمة الأماكن
    3. يضيف تفاصيل من ENRICHISSEMENT_LIEUX لكل مكان
    4. يبني قائمة "raisons" (لماذا هاد التوصية):
       - budget عالي + عمر كبير → Ville
       - budget صغير → Nature
       - متزوج → Ville
       - عازب + شاب → Nature
       - من أوروبا → Ville
    5. إذا المستخدم مسجل دخول: destinations_visited + 1

  يرجع JSON بـ:
    - type_destination (Ville/Nature)
    - ml_used (True/False)
    - ml_accuracy (مثلا 85.5)
    - raisons_classification (لماذا؟)
    - profil (بيانات المستخدم)
    - lieux (قائمة الأماكن كاملة)
    - count (عدد الأماكن)

GET /api/groups
  → يجيب كل مجموعات السفر من DB
  → يضيف لكل مجموعة قائمة أعضائها

POST /api/groups  (إنشاء مجموعة)
  → يستقبل: name, dest, date, max, desc
  → يحفظ المجموعة في جدول groups
  → يضيف المنشئ تلقائيا كعضو أول
  → يرجع بيانات المجموعة الجديدة

POST /api/groups/<id>/join  (الانضمام)
  → يتحقق المجموعة موجودة
  → يتحقق المستخدم ليس عضوا بالفعل
  → يتحقق المجموعة غير ممتلئة (current < max)
  → يضيف المستخدم ويزيد current + 1
  → يزيد groups_joined + 1 للمستخدم

GET /api/my-groups
  → يجيب مجموعات المستخدم الحالي (منشئها أو عضو فيها)

POST /api/groups/match  (إيجاد مجموعة متوافقة — KMeans + Cosine Similarity)
  ⭐ ذكاء اصطناعي حقيقي — مو قواعد بسيطة

  المدخلات: age, budget, sexe, marie, type_activite, niveau, interets

  الخطوة 1 — KMeans Clustering:
    → درّب على data.csv بـ 4 features: âge, budget, sexe, marié
    → 4 clusters — كل واحد عنده type_destination dominant:
        Cluster 0 → Ville  |  Cluster 1 → Nature
        Cluster 2 → Ville  |  Cluster 3 → Nature
    → يتنبأ بـ cluster المستخدم → يعرف نوع وجهته المفضلة

  الخطوة 2 — encode_profile_vector() (24 بُعد):
    * âge + budget normalisés
    * type_activite one-hot (6 قيم)
    * niveau one-hot (4 قيم)
    * intérêts multi-hot (12 قيم)

  الخطوة 3 — Cosine Similarity:
    → يحسب التشابه الرياضي بين vecteur المستخدم وvecteur كل مجموعة
    → ناتج 0 (مختلف) → 1 (متطابق)

  الخطوة 4 — KMeans Bonus:
    → cluster متطابق + type_destination = +20%
    → مجموعة Mixte = +8%

  الخطوة 5 — Pénalités:
    → خارج tranche d'âge → -25%
    → budget غير كافي    → -20%

  النتيجة: score 0-100 + "IA prédit Nature pour ton profil ✓"

GET /api/buddy-stats
  → إحصائيات: كم مستخدم يريد Ville / كم يريد Nature

║  15.1  FETCH API — كيفاش كيتواصل JavaScript مع Flask
╚─────────────────────────────────────────────────────────────────────────────╝

المشروع كيستخدم Fetch API (Vanilla JS) بدون jQuery أو Axios.

مثال كامل (إرسال بيانات للـ backend):

  const res = await fetch('/api/predict', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ age: 25, sexe: 'Homme', budget: 2500, marie: 'Non', region: 'Maroc' })
  });
  const data = await res.json();

  → fetch() ترجع Promise (عملية غير متزامنة)
  → await تنتظر النتيجة (بدون تجميد الصفحة)
  → res.json() تحول الجواب لـ JavaScript object
  → async/await بدل .then().catch() (أسهل للقراءة)
